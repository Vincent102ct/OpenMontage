Fourteen sentence SRT cues use character-distributed timing, not verified word
alignment. Brief `cue_start`/`cue_end` are inclusive **1-based within the segment**.
The compiled narration reference records absolute SRT cue numbers, exact
character offsets and exact text, including boundary whitespace. Offsets are
zero-based Unicode code points, with an exclusive end (not UTF-8 byte offsets
or JavaScript UTF-16 units). Concatenating
the shot spans for a segment reproduces its canonical text byte-for-text after
UTF-8 serialization. On-screen text is an independent array, never narration.

Interior cuts use the actual estimated SRT boundaries; measured segment
boundaries stay exact. The first scene starts at 0, each segment's final scene
holds through its following .4 s gap, and the final scene holds the .5 s tail.
Thus visual coverage is contiguous without inventing word-level precision or
padding the narration. Six-decimal display is arithmetic precision, not a claim
of six-decimal acoustic alignment. Frame quantization is a later renderer concern.

## Contract and validation

Each scene has an authored stable `SC_xxx`, format/segment, visual start/end,
unambiguous narration span/timing basis, claim/source/entity/event/continuity
IDs, visual purpose, subject/setting/framing/camera/action/transitions, required
canonical elements, intended representation, unresolved asset requests,
on-screen text, risk flags and pending review. IDs are not regenerated from
list positions. Required asset IDs derive from stable scene IDs.

The plan binds normalized JSON content hashes of package/manifest/brief and the
original narration/SRT file records. It carries the unchanged selected canonical
claim/source/entity/event/rule context, including qualifiers, contradictory
sources and source verification statuses. Evidence source IDs support claims;
they are **not** evidence of possessing a corresponding image or its license.

Validation requires both JSON Schema **and** `validate_plan`:

- Package/format/order/text/claims/status/qualifier/entity/event/rule metadata
  must match M2.1/M2.2. Duration is sample-derived, finite, ordered and in target.
- Cues must map verbatim to the entire selected narration. Changing SRT text
  or times under an old declared hash fails; LF/CRLF reading is handled explicitly.
- Directions partition cues once in order; every beat's claims remain covered.
  Required elements/events must exist, be allowed by the beat and share a claim.
- Scenes cover [0, total] exactly, with positive duration and no gaps/overlaps;
  narration stays within its scene. Stored plans cannot drift from the brief.
- Context needs an explicit context label; illustration/reconstruction needs an
  evidence label, except the constrained non-representational `visual_pause`
  (no overlays, canonical elements or external media). AI preference requires reconstruction classification, still
  unresolved and pending. Free-text accuracy is not inferred by an NLP heuristic.
- Asset `status` is always `unresolved`, `resolved_asset` null. Extra image URL,
  path, license or creator fields fail the M2.3 contract. Factual, listening,
  publication, visual-plan and in-scope human continuity reviews remain pending.

Contract enums reserve Short/Long and 9:16/16:9. The compiler explicitly rejects
Long in M2.3; no Long planning implementation is included.

equal-duration cuts. Typography/comparison shots have distinct information roles.

Asset search priority is explicit: authentic historical evidence → public-domain
institutional → license-verified Wikimedia → other freely licensed media →
local library → AI reconstruction only as a separately reviewed future fallback.
Historical-document requests start with authentic evidence. Appropriate neutral
editorial diagrams can request local graphics; historical footage cannot prove
an unknown action merely by ranking above illustration in the source list.
Nothing is searched/downloaded/generated in M2.3.

## Run and deliverables

From repository root, with existing Python dependencies/M2.2 narration artifacts:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/visual_scene_plan.py `
  examples/master-story/lead-masks-1966/master_story.json `
  projects/story-053-short/artifacts/short_timed_manifest.json `
  examples/master-story/lead-masks-1966/short_visual_brief.json `
  --output-dir projects/m23-visual-plan/pilot
```

Exit 0: technically valid plan. Exit 1: rejected input/plan; not silently repaired.
Default output: `projects/<story-id>-visual-plan/`. Relative media paths resolve
against `--media-root` (default repository root); absolute manifest paths must
exist on the current machine. Moving narration assets requires an explicit,
revalidated manifest, not an unrecorded path rewrite.

Outputs in the review directory:

1. `visual_scene_plan.json` — machine-readable canonical plan.
2. `storyboard.md` — every shot/time/narration/visual/why/asset plus risk references.
3. `asset_requirements.json` — 11 unresolved requests, categories and explicit
   fallback policies; `media_ready: false`.
4. `continuity_review.json` — in-scope canonical rules and per-shot review flags.
5. `validation_report.json` — coverage, input files, all M2.2 gates and pending reviews.

Creative directions are committed-source candidates; generated review outputs
stay under Git-ignored `projects/`. No shared pipeline checkpoint is written
through the unreviewed WIP code. This is a standalone M2 contract implementation,
not an execution/promotion of the old cinematic production project.
