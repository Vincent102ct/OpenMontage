# P2.2 — Fiction Story Package and Human Editorial Review

Status: functionality accepted; publication finalized with private drafts excluded.
Packages still require human editorial review; acceptance of the feature approves no story.
Baseline: `coding` at `1cd2454` (P2.1 accepted). P3 not started.

Author-provided fiction gets its own canonical package, separate from the
historical Master Story Package used by STORY 053. A Story Bible draft (written
by a person or an AI assistant) is imported, checked against the original story
span by span, and stored as a versioned draft package with Short and Long plans.
The reviewer then records Accept / Reject / Defer / Answer decisions in Studio.
Nothing here starts TTS, asset generation, rendering or publishing, and nothing
is approved automatically.

Windows usage: [STUDIO_WINDOWS.md](../STUDIO_WINDOWS.md#review-the-story).

## Flow

```text
Saved request (P1) → Prepare Story Draft (P2.1 intake) → Import Story Bible draft (P2.2)
  → fiction_package/v1 (validated, draft) → Story Review decisions (append-only log)
```

If intake has not run, building a package returns `intake_missing` and the
review screen says so. No package is fabricated.

## Fiction package contract

Reused from the historical model:
- stable IDs;
- narrative segments (the intake `SEG_####` segments, copied with spans and SHA-256);
- characters, locations and objects;
- continuity rules;
- Short/Long format plans;
- source traceability.

Specific to fiction:

| Concept | Representation |
| --- | --- |
| Provenance | Source path + SHA-256, production request SHA-256, intake report SHA-256, draft SHA-256 and authoring note. `authorship.author` is always `production_requester`; no invented identity |
| Relative time | `events[].narrative_order` (1..n, must follow narration order), `story_phase` (backstory / present / aftermath), `time_markers` that must appear in the story. No calendar dates |
| Facts vs claims | `facts[].kind`: `narrated_event`, `character_claim` (needs `reported_by`), `later_revelation` (needs `reported_by`; must be revealed after any claim it conflicts with), `ambiguous` (must be tied to an open question). Conflicts are symmetric |
| Ambiguity | `ambiguities[]` always `unresolved` in the package; only a reviewer's answer records an interpretation |
| Dialogue | Verbatim text, `channel` (speech, unseen voice, text message, writing, sound effect), speaker and `attribution_status`: `proposed`, `unresolved` (no speaker) or `not_applicable` |
| Horror sound | `sound_cues[]` (diegetic, voice, electronic, ambience, silence) linked to events |
| Staging | Locations carry `source_details` plus `proposed_staging`; format beats carry action, environment, camera, uncertainty, reveal flag and planned silence |
| Stickman preparation | `stickman_production`: style constant, primary output = character animation in horror environments, forbidden primary treatments (documentary motion graphics, text slideshow, stock montage, static zoom, infographic replacement), per-character silhouette, persistent props and consistency rules, uncertainty policy, `preliminary_not_rendered` |
| Coverage | `coverage.complete` is always `false`; `missing` combines the draft's own list with automatic gaps (unlinked segments, quoted lines without entries, unresolved speakers, open questions) |

Every semantic item cites evidence `{segment_id, char_start, char_end, quote}`.
Drafts may cite a unique quote, `SEG_0004`, a range `SEG_0002..SEG_0007` or
`{segment_id, quote}`. The resolver refuses missing or ambiguous quotes.

### Format plans

- **Short:**
  - `FMT_SHORT`, 9:16, target 45–60 s;
  - estimate = syllables ÷ 4.35/s + planned silences. The 4.35 rate comes from STORY 053's measured Piper narration: 1857 syllables over 426.55 s.
- **Long:**
  - `FMT_LONG`, 16:9, `target_seconds: null` because duration is unknown until TTS;
  - must cover every story segment in source order, except exclusions tied to a proposed edit.
- **Narration:**
  - `verbatim` text must equal the cited source spans exactly;
  - `authored_proposal` text is labelled as such and cites its sources.
- **Edit dependencies:** a plan that uses or excludes a segment touched by an intake edit must list it in `depends_on_changes`.
- **Short ⊆ Long:** the Short may only use characters, events, objects and locations that also appear in the Long.
- **Approval:** plans are `draft` and `approved: false`; review decisions do not rewrite them.

### Anti-fabrication checks

The validator rejects any of the following:
- years, ISO dates, URLs or DOI/ISBN identifiers in authored text that do not occur in the story;
- unknown fields such as `date`, `sources` or `timeline` (rejected by the schema);
- aliases or time markers not found in the story;
- quotes that do not match their span;
- edited segment text or verbatim narration.

## Storage

| Path | Written |
| --- | --- |
| `artifacts/fiction_package/v1/fiction_story_package.json`, `story_bible_draft.json`, `fiction_package_report.json` | Once, atomically. Same draft again → `already_prepared`; different draft → `package_exists`; edited files or changed inputs → `existing_output_invalid`. Never overwritten |
| `artifacts/story_review/v1/decisions/000001.json`… | One new file per decision |

Each decision record holds:
- `target_id`, `decision` (`accept`, `reject`, `defer`, or `answer` + text for questions);
- `supersedes`, `previous_sha256` (hash chain), `input_hashes` (source, request, intake report and, for package targets, the package);
- `reviewer: "local Studio user"`, `recorded_at` and `production_effect: "none"`.

Rules:
- **Changing a decision** requires naming the decision being replaced. Otherwise you get `stale_decision` (409), so an old page cannot silently overwrite a newer decision. Earlier records stay as history.
- **Tampering:** an edited, missing or renumbered decision file makes the log `log_invalid`. Nothing more is recorded and nothing is rewritten.
- **Stale decisions:** decisions made against a replaced package are shown as `stale` and do not count.
- **Questions** stay `open` until answered with non-empty text; `defer` keeps them unresolved.
- **Review status** becomes `decisions_recorded` only when every target is accepted or rejected and every question is answered. Even then, production does not start.

P1 and P2.1 files are never written by P2.2. Backlot is unchanged and read-only;
the new folders sit under `artifacts/` subdirectories, which Backlot ignores.

## Studio

My Productions → **Story Review** (Full story productions only) shows:
- review status, the "decisions never start production" note, and decision counts;
- **Missing or incomplete**: intake semantic gap, draft gaps, automatic gaps and open item counts;
- **Import Story Bible draft (.json)** when no package exists, with validation problems listed on failure;
- the original story (read-only) and the proposed working text (all proposed edits applied; preview);
- proposed edits with before/after and Accept / Reject / Defer;
- interpretation questions (intake + package) with Record answer / Defer;
- Story Bible collections with source spans and Accept / Reject / Defer;
- Short and Long drafts by chapter and beat:
  - each narration is marked **Verbatim source text** or **Authored proposal, not source text**;
  - each beat shows its staging;
  - each plan shows its duration estimate;
  - each plan has Accept / Reject / Defer;
- Stickman Horror preparation, marked preliminary and not rendered.

API (same-origin JSON POSTs only):

| Method | Path | Result |
| --- | --- | --- |
| POST | `/studio/api/productions/{id}/fiction-package` | 201 created / 200 already prepared / 409 `intake_missing`, `package_exists`, `existing_output_invalid` / 422 `invalid_draft` + `problems` |
| GET | `/studio/api/productions/{id}/fiction-package` | Verified package and report |
| GET | `/studio/api/productions/{id}/review` | Review view (`state: intake_missing` when intake has not run) |
| POST | `/studio/api/productions/{id}/review/decisions` | 201 / 409 `stale_decision`, `log_invalid` / 404 `unknown_target` / 422 `invalid_decision` |

CLI:
- `python -m studio fiction <id> --draft <file>`
- `python -m studio review <id>`

## Private drafts and publication boundary

Author stories and their AI-authored Story Bibles are private project data. They
are never examples to publish. Keep original draft bytes under the already
ignored `projects/_private_story_drafts/<draft-id>/story_bible.draft.json`.
Before retiring an untracked copy elsewhere, copy without editing and compare
SHA-256 values. Never add private drafts with `git add -f`.

The CLI accepts only plain `.json` files beneath the configured projects root's
`_private_story_drafts/` directory. It refuses traversal, paths outside that
folder, alternate data streams, symlinks/junctions and files over 2 MB. The browser
file picker sends JSON content; the API never reads a client-supplied disk path.
Successful imports link source/request/intake hashes and the canonical JSON
content hash of the draft. The canonical hash is independent of whitespace and
key order; use the physical file SHA-256 to verify a byte-preserving relocation.
Saved drafts are rechecked against provenance on every package read.

No private pilot name, narrative, Story Bible or screenshot is shipped. Tests and
the published screenshot use a separate synthetic workshop story. A fresh clone
needs no private project data. Importing the private draft on a real production
remains an explicit user action; finalization does not perform that import.

## Remaining limits and blockers

- **The Story Bible is an AI-authored proposal.** No independent semantic check
  exists. Every item is unapproved until a reviewer decides.
- **Decisions don't feed back yet:** they are not merged into a "reviewed package v2". Approved
  edits/items are only visible through the review state. Producing a reviewed
  package, and TTS measurement of the Short, belong to the next milestone.
- **The 4.35 syllables/s rate comes from STORY 053's Piper voice**; every new
  production needs its own duration measurement in a later authorized milestone.
- **Status docs not updated:** `ROADMAP.md`, `DECISIONS.md`, `WORKLOG.md`, `SOURCE_MAP.md` and
  `docs/ARCHITECTURE.md` hold unrelated M2.4 WIP and were not edited. Entries to add later:
  - ROADMAP: `[x] P2.2 fiction story package + human review (draft; decisions recorded, not applied)`.
  - DECISIONS: fiction uses a separate package (no sources or dates); the AI-authored draft is imported and validated against spans; decisions are append-only with explicit supersede; no checkpoints; nothing auto-approves or starts production.
  - SOURCE_MAP: `lib/fiction_story.py`, `studio/fiction.py`, `studio/review.py`, `schemas/story/fiction_story_package.schema.json`, `tests/studio/fiction_fixture.py`.
