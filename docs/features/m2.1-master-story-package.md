# M2.1 — Canonical Master Story Package

Date: 2026-10-22. Baseline `coding` / `5316fe9`. Pilot: STORY 053 — Lead Masks Case,
Niterói, Brazil, 1966.

## Goal

Research a story once; produce both a YouTube Short and a Long-form video from one
source of truth. Short and Long reference the same sources, claims, characters,
locations, objects and timeline by canonical ID and cannot carry contradicting data.

Out of scope for M2.1: image/video generation, rendering, TTS changes, Short/Long
rendering pipeline, the uncommitted Evidence Canon / footage-led WIP, paid APIs.

## Data model

One JSON file per story, validated by
`schemas/story/master_story_package.schema.json` and `lib/master_story.py`.

| Section | Canonical IDs | Content |
| --- | --- | --- |
| `sources` | `SRC_*` | Title, publisher, date, URL or reference, type, reliability, **verification** (status, date, method, note) |
| `claims` | `CLM_*` | Verbatim claim text, one epistemic `status`, supporting / contradicting sources, qualifier, optional event |
| `timeline` | `EVT_*` | `date_start` [+ `date_end`], precision, `date_kind` (event / reported_event / document / publication), claims, entities |
| `entities` | `CHR_*`, `LOC_*`, `OBJ_*` | Characters, locations, objects; each grounded in ≥1 claim; aliases |
| `continuity_rules` | `CR_*` | `requires_claims` (machine-checked) or `human_review` |
| `master_narrative.segments` | `SEG_*` | Narration text, claims, entities, events, sources, estimated seconds |
| `formats.short` / `formats.long` | — | Format plan: package ID+version, aspect ratio, target duration, ordered `segment_ids` only |

Epistemic statuses (same six names as the Evidence Canon WIP, not ranked):
`DOCUMENTED_FACT`, `REPORTED_ACCOUNT`, `LATER_INTERPRETATION` (interpretation),
`HYPOTHESIS`, `LEGEND`, `UNKNOWN`. Facts, accounts, interpretations, hypotheses,
legends and unknowns are separate values of one field, so a claim cannot be both.

**Why formats hold only segment IDs:** a format plan
(`schemas/story/format_plan.schema.json`, `additionalProperties: false`) cannot
restate a claim, status, entity, date or text. Everything a Short or Long shows
is resolved from the package, so the same ID always means the same record.

## Validation rules (`python -m lib.master_story validate <file>`)

| Group | Fails when |
| --- | --- |
| Schema | Missing fields, unknown status, malformed ID/date, a format carrying extra data |
| IDs | Duplicate ID anywhere in the package; entity prefix not matching its kind |
| Sources | Unresolved source; any non-`UNKNOWN` claim without a supporting source; segment cites a source not cited by its claims |
| Claims ↔ events | `claim.event_id` and `event.claim_ids` disagree; unresolved claim/entity |
| Timeline | Events not chronological by `date_start`; `range` without `date_end` (or reverse) |
| Entities | Unresolved claim; a segment/event naming an entity with no shared claim |
| Segments | No claims unless `nonfactual: true`; unresolved/ungrounded entity, event or source |
| Continuity | `requires_claims` rule incomplete or violated in the master narrative or a format |
| Formats | Wrong kind/aspect ratio (Short 9:16, Long 16:9), other package ID/version, unknown or reordered segments. Estimated duration outside target is a **warning** (`summary.warnings`, `DURATION_ESTIMATE`) since M2.2.1; real duration is gated on measured audio in M2.2 |
| Short vs Long | A claim used by the Short is absent from the Long |

`resolve_format(package, "short"|"long")` (CLI `resolve`) returns one shared view:
segment texts plus the canonical claims, sources, entities, events and applicable
continuity rules. Later Short/Long production steps should consume this view.
`validate_external_format()` checks a separately stored plan against a package.

Limits: the validator checks references and declared statuses, not truth. It cannot
tell whether narration wording keeps a qualifier or adds an unlisted fact; those are
`human_review` rules and editorial review. Durations are estimates until audio is
synthesized and measured.

## Acceptance criteria

1. The pilot package validates automatically (CLI exit 0). **Met.**
2. Short and Long resolve shared IDs to identical claim/entity/event records. **Met (test).**
3. Every claim has one of six statuses; every non-unknown claim cites a listed source. **Met.**
4. A Short that drops a required qualifier, reorders/invents segments, targets another
   package version or uses a claim the Long lacks is rejected. **Met (tests).**
5. No historical fact, source or narration invented. **Met (verbatim check).**

Tests: `tests/lib/test_master_story.py` (25).
